# Database Design

## Database decision

MySQL 8.4 is the authoritative relational database. Prisma uses `provider = "mysql"`. Binary documents remain in private S3; only metadata and object keys are stored in MySQL. Blockchain data is limited to anchor metadata and transaction references.

## Design principles

- Normalized records and explicit foreign keys.
- String IDs generated by the application/Prisma (`cuid`) to avoid enumerable public identifiers.
- UTC `DateTime` fields; explicit farm time zone.
- Decimal for doses, concentrations, quantities, and MRL values—never floating point.
- Enumerations for stable workflow states; reference tables for researched domain values.
- Soft state transitions (`SUSPENDED`, `REVOKED`, `SUPERSEDED`) rather than deleting history.
- Immutable snapshots for eligibility/certificate explainability.

## Entity groups

### Identity and farms

- `User`, `RefreshToken`, `UserPlatformRole`
- `Farm`, `FarmMember`, `FarmMemberRole`
- A unique `(farmId,userId)` membership supports multiple role rows such as owner and manager.

### Livestock and veterinarians

- `Animal`, linked to `Species` and optional `Breed`
- `VeterinarianProfile`, `VeterinarianServiceArea`, verification document through `FileObject`
- Verification status gates clinical operations at service level.

### Veterinary workflow

- `TreatmentRequest` and attachment join records
- `VeterinaryCase`, `CaseMessage`, message attachments
- `Diagnosis`, `Prescription`, `PrescriptionItem`
- `Treatment`, `TreatmentAdministration`
- Prescription intent and actual administration are separate.

### Reference and compliance

- `Species`, `Disease`, `AntimicrobialClass`, `Drug`, `DrugProduct`
- `RegulatorySource`, `WithdrawalRule`, `MrlReferenceRule`
- `ReferenceDataVersion` supports provenance/import history.
- `MilkEligibilityCheck` and `EligibilityTreatmentEvaluation` capture all evaluated blockers.
- `MilkEligibilityCertificate` retains lifecycle and canonical payload/hash.

### Monitoring and proof

- AMU is derived reproducibly from administrations. `AmuAggregation` is an optional materialized period/category result with methodology version; administrations remain authoritative.
- `Alert`, `AuditLog`, `DomainEvent`
- `BlockchainAnchor`

## Critical constraints

- Unique veterinarian registration council/number combination.
- Unique farm membership per farm/user and role per membership.
- Only one active case per accepted request.
- Unique public certificate verification ID and certificate number.
- Unique blockchain anchor per record type/record/hash/chain.
- Withdrawal rules carry jurisdiction, product/species/food/route/formulation/use conditions, source, version, and verification state.
- MRL records have no measured-value relationship and are never referenced by eligibility checks.

## Schema scope

The initial Prisma schema defines the full aggregate skeleton but intentionally omits speculative tables and fake reference seed values. Complex permission enforcement, veterinarian verification, state transitions, AMU calculation, and eligibility logic will live in services and be covered by later migrations/tests.

## Index strategy

Initial indexes cover farm/animal ownership, veterinarian status/service area, request/case status, administration time, active withdrawal/eligibility lookups, certificate verification, alerts, audit subject/time, and AMU period dimensions. Query plans will be measured before adding redundant indexes.

## Migration strategy

`prisma/migrations/0001_initial/migration.sql` is generated from the schema and committed as the baseline. Later schema changes use named Prisma migrations; production uses `prisma migrate deploy`. Reference imports use explicit versioned import jobs and never destructive reseeding.
