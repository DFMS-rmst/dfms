# Milk Eligibility Certificate System

## Issuance boundary

A farm owner/manager or platform administrator may request issuance, but the backend first invokes the existing eligibility service. Only the current `ELIGIBLE_FOR_MILK` result can issue. `TREATMENT_ACTIVE`, `UNDER_WITHDRAWAL`, `RULE_NOT_FOUND`, and `REVIEW_REQUIRED` fail closed. The certificate service contains no withdrawal calculation and never treats an MRL, foreign example, cattle-only rule for buffalo, or statutory minimum awaiting review as sufficient evidence.

One certificate is idempotently returned per eligibility evaluation. A newer eligible evaluation may issue a new version and supersede an older active certificate. A new blocking eligibility evaluation revokes every active certificate for the animal and preserves its record, actor/system cause, time, and reason.

## Immutable evidence snapshot

The versioned snapshot contains certificate number and issuance instant; animal tag and species; farm name; source eligibility evaluation/time/method version/eligible-from date; and each relevant treatment, drug, completion time, withdrawal end, and rule/source snapshot. It deliberately excludes contact details, chat, mutable current relations, presigned URLs, credentials, and measured-residue fields.

The required prominent disclaimer is:

> This certificate represents milk eligibility based on recorded treatment history and configured withdrawal-period reference rules. It does not represent laboratory residue testing.

## PDF and lifecycle

PDFKit renders the immutable snapshot server-side and embeds a QR generated by `qrcode`. The authenticated PDF endpoint streams the document and records an audit event; it does not expose an S3 object or credentials. This on-demand approach avoids permanent URLs and duplicate binaries. If PDFs are persisted later, they must use the existing private S3 metadata and authorized presigned GET flow.

Statuses are `ACTIVE`, `REVOKED`, and `SUPERSEDED`. No expiry was invented. Status expresses current certificate validity; blockchain integrity is a separate fact.
